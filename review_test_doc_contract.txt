■ 対象範囲
  documents/ と contracts/ の以下を対象に、tests.py の既存カバレッジと未カバー分岐を洗い出す。
    - views.py（保管 UploadStep1/2、単独編集、一括編集、検索、ダウンロード/プレビュー/一括DL）
    - api.py（OptionList / ChunkUpload / Detail / RelatedSearch〈契約書のみ〉）
    - services.py（can_delete, scoped_get_object_or_404, *_edit, *_is_dirty, calculate_expiry_date,
      filter_valid_related_ids, sync_related_contracts, build_zip_archive 等）
    - search_services.py（build_queryset, apply_sort, _apply_notice_filter）
    - forms.py（UploadStep2Form / SearchForm）
    - models.py（Document / Contract / ContractRelation）
    - 削除系（DeleteView / EditDeleteView / BaseDeleteView、一括編集の削除マーク）
  共通基底（core.record_views / core.bulk_edit_views / core.upload_views）は documents/contracts の
  テストから間接的に叩かれる範囲のみ扱う（core 側の直接テストは別監査）。

■ 監査方法
  1. views/api/services/search_services/forms/models と、委譲先の core 基底クラスを通読。
  2. documents/tests.py（3635行）・contracts/tests.py（3530行）のテストクラス・メソッドを全列挙。
  3. 実装の各分岐（特に権限拒否・異常系・境界値）に対応するテストの有無を突き合わせ。
  4. documents ↔ contracts で「片方だけテストがある」非対称を抽出。
  ※ 本レポートはレポートのみ。テスト追加は行っていない。
