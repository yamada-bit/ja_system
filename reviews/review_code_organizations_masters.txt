No.1 【中】 分類コード / カテゴリーコードの一意性が「部署」を無視した全体一意になっている
  対象:
    masters/models.py:54   UniqueConstraint(fields=["code"], condition=Q(is_deleted=False))
    masters/models.py:92   同上（Category）
    masters/forms.py:88    GroupForm.clean_code  → Group.objects.filter(code=code, is_deleted=False)
    masters/forms.py:195   CategoryForm.clean_code → 同様
  根拠:
    Rev1.2 で分類・カテゴリーは「部署単位で管理」に変更され（models.py:24-29 の docstring、
    xlsx 分類管理!B73-75）、非管理者は自部署の分類・カテゴリーしか一覧・編集できない
    （masters.services.department_scope_ids、BaseScopedMasterEditView）。
    ところが一意制約と clean_code は department を条件に含めず code だけで全体一意にしている。
    このため部署Bの一般ユーザーが code="01" を登録しようとすると、部署Aが既に持つ
    （B からは一覧にも表示されない）分類のせいで「この分類コードは既に登録されています。」
    となり登録できない。ユーザーには理由が見えない不可解なエラーになる。
    → xlsx B119/B161「重複登録・重複更新は不可」が全社一意なのか部署内一意なのか要確認。
      部署内一意が正なら constraint を (department, code) に、clean_code も
      scope_queryset_by_department で絞ってから重複判定する必要がある。

  【対応済み】2026-09-10、ユーザー確認の結果「部署内で一意」に確定。
    - masters/models.py: Group/Category の UniqueConstraint を fields=["department","code"] に変更
      （condition=Q(is_deleted=False) は維持）。制約変更は masters/migrations/0001_initial.py の
      AddConstraint を直接書き換えて反映（本番リリース前のためマイグレーションは0001に集約する運用）。
      department=NULL（Rev1.2移行前データ）同士は Postgres の NULL 非同一仕様で制約対象外になるが、
      移行後の新規・編集は必ず department を持つため許容（コメントに明記）。
    - masters/forms.py: _effective_department()（管理者=送信値／編集=instance／非管理者の新規登録=
      ログイン者の部署 の順で実効部署を解決）と _duplicate_master_code_exists() を新設し、
      GroupForm/CategoryForm.clean_code の重複判定を同一部署スコープに変更。
    - masters/views.py: GroupRegistView/GroupEditView に extra_form_kwargs で employee を渡すよう追加
      （CategoryRegistView/EditView は既存）。
    - masters/tests.py: 部署別に同一コード可・同一部署内は不可・非管理者は自部署基準、の各テストを追加。
      Master(Edit)IntegrityErrorViewTests の衝突フィクスチャを同一部署で作るよう修正。

No.2 【中】 一覧の「文書件数」列・削除可否判定が、ゴミ箱保管中（is_deleted=True）の
           文書・契約書まで数えている
  対象:
    masters/views.py:37-38    _group_queryset_with_counts()
                              Count("documents", distinct=True) / Count("contracts", distinct=True)
    masters/views.py:210-211  _category_queryset_with_counts() 同上

    比較: core/notice_services.py:83-87 は同種の集計で is_deleted=False を明示している。
    → Count(..., filter=Q(documents__is_deleted=False)) 等に揃えるか、
      仕様上ゴミ箱分も数えるのが正しいなら「文書件数」列表示と整合するようコメントで明記。

  【対応済み】2026-09-10、ユーザー確認の結果「ゴミ箱（is_deleted=True）は除外」に確定。
    - masters/views.py: _group_queryset_with_counts()/_category_queryset_with_counts() の
      doc_count/contract_count を Count(..., filter=Q(<rel>__is_deleted=False)) に変更（Q を import）。
      blocking_count() はこの annotate を参照するため削除ブロック判定も同時に是正される。
    - masters/tests.py: ゴミ箱の文書／契約書が item_count に数えられず、削除もできることを検証する
